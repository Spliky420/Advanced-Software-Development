The Research Library is the Personal Finance Assistant feature for saving and reading financial research. A user can add, edit, delete and filter research documents such as articles, guides, reports, news, research notes, filings and whitepapers. Each document stores a title, a source or publisher, a document type, an optional published date and the full body text. The library is single-user in Release 1, so every document belongs to the default user.

The Research Library can summarize a document with the local AI model through Ollama. Summarization follows a Plan, Act, Observe and Adapt loop. A short document of up to 3000 characters is summarized directly in one model call. A long document is summarized map-reduce style: it is split into chunks of about 2000 characters, at most six chunks, each chunk is summarized first, and then the chunk summaries are combined into one final summary.

Every Research Library summary contains a short summary paragraph and three to six key points. The model is instructed to describe only what the document says, never to give financial advice or recommendations, never to invent a fact or figure, and never to perform arithmetic. The latest summary is saved on the document, and every model call is recorded in the document AI log for auditing.

Research Library retrieval search finds passages across all saved documents by meaning rather than by keyword. Documents are split into chunks of 800 characters with 100 characters of overlap and embedded with the nomic-embed-text embedding model. A search embeds the query and ranks chunks by cosine similarity, and every similarity score is computed in Python rather than by the model. Indexing happens automatically when a document is created or edited.

The Research Library glossary lookup lets a user define a financial word found inside a document. The user double-clicks a word or selects a phrase in the document, and the Research Library backend calls the glossary_lookup tool on the shared MCP server. That tool reads the definition from the Financial Glossary feature. The term must appear in the document, and the Research Library may only call the glossary_lookup tool, which is its MCP tool boundary.

The Research Library ask feature answers questions from the shared RAG knowledge base. The backend retrieves context chunks from the shared RAG server, checks in Python how many of the question terms the retrieved chunks contain, and sets a confidence category of High, Medium or Low from that coverage. When the retrieved context does not cover the question, the library returns an insufficient-context response and does not ask the model to answer.

The Research Library runs as three containers: a frontend served by nginx on port 8030, a Flask backend API on port 8031 and a SQLite database. The shared MCP server, the shared RAG server and the local AI model run on the host outside Docker. The backend reaches the MCP server and RAG server through host.docker.internal, and MCP and RAG modes can be switched off with the MCP_ENABLED and RAG_ENABLED settings, which continuous integration does.
