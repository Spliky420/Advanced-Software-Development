Notes on reading the output above
======================================================================
- Section 1: "AllowInsecure: True" appears only on the four internal backends
  (External: False). They have no public address -- their FQDN is under
  ".internal." -- so plain HTTP is only possible between apps inside the
  Container Apps environment (frontend nginx -> backend). Every external app
  has AllowInsecure: False.
- Section 1: maxwell-backend and hyunwoo-backend are external by design:
  those two frontends call their backend from the browser, so the browser
  needs a public HTTPS address (see scripts/deploy/cloud-rewrites.sh).
- Section 1: every app pulls images with the id-asd2026-acrpull managed
  identity; no app has a registry password or any stored secret (AppSecrets 0).
- Section 2: the 404 body is Azure's own "stopped or does not exist" page --
  the public ingress has no route to an internal app.
- Section 5d: the two matches are in LeHoaLong's detect-secrets report. They
  are AWS's published documentation example key (AKIAIOSFODNN7EXAMPLE) and a
  dummy password, quoted as test fixtures and marked
  "pragma: allowlist secret". They are not credentials.
- Section 5a: the only "secrets." match is a comment stating the workflow
  uses no secrets.
