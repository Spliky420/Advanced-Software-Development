# Dependencies — pip-audit — 2026-10-22

**Tool:** pip-audit 2.10.1 (PyPI advisory database via OSV)
**Scope:** `LeHoaLong/backend/requirements.txt` and `LeHoaLong/tests/requirements.txt`,
each resolved with its full transitive dependency tree
**Result:** 4 distinct advisories in 3 pinned packages before, **0 after**,
fixed by upgrading the pins.

## Before

pip-audit prints each advisory once per description source, so the raw
output shows 6 and 8 lines. These are the distinct advisories:

| Package | Pinned | Advisory | Fixed in | In | What it is | Did it reach us? |
| ------- | ------ | -------- | -------- | -- | ---------- | ---------------- |
| Flask | 3.0.3 | PYSEC-2026-2151 | 3.1.3 | both | `Vary: Cookie` not set on some session accesses, so a caching proxy could serve one user's page to another | No: the backend never uses `session`. Upgraded anyway, because "unused today" is not a property anything enforces. |
| requests | 2.32.3 | PYSEC-2026-1872 | 2.32.4 | both | A crafted URL can leak `.netrc` credentials to a third party | Low: the backend only calls URLs from its own config (Ollama, MCP, RAG, multi-agent), but the Release 2 multi-agent client adds another. |
| requests | 2.32.3 | PYSEC-2026-2275 | 2.33.0 | both | `extract_zipped_paths()` uses a predictable temp file name | No: only affects direct callers of that function. |
| pytest | 8.3.3 | PYSEC-2026-1845 | 9.0.3 | tests | Predictable `/tmp/pytest-of-{user}` directories allow local DoS or privilege gain on shared UNIX hosts | CI runners are single-tenant, but the fix is free. |

`gunicorn 22.0.0`, `mcp 1.30.0` and every transitive dependency (Werkzeug,
Jinja2, httpx, anyio, pydantic, ...) came back clean.

## Fix

| Package | Before | After |
| ------- | ------ | ----- |
| Flask | 3.0.3 | 3.1.3 |
| requests | 2.32.3 | 2.34.2 |
| pytest | 8.3.3 | 9.1.1 |

Each moved to the current release rather than the minimum fixed version, so
the next advisory against an older line does not land straight away. Both
files pin Flask and requests identically, as before, so the tests run
against the versions the container ships.

## Verified

- In a fresh virtualenv with `tests/requirements.txt`: Flask 3.1.3,
  Werkzeug 3.1.9, requests 2.34.2, pytest 9.1.1. **421 passed.**
- `backend/requirements.txt` (gunicorn, `mcp`) added to the same
  environment: `pip check` reports no broken requirements, and the MCP
  client transport (`mcp.client.streamable_http`) imports.
- Not verified: a Docker build of the backend image, because Docker Desktop
  was not running. CI's `images` job builds it on push.
